# 窗口重建、静态动态插入与异常标签

2026年10月28日核对。依据当前网页窗口包、两模型服务器 `demoNew03.py` / `demo11.py` / 训练入口 / 损失代码，以及老师逐字谈话。本文解释现有机制，不更改实验结果。

## “单个窗口重建”到底用哪个窗口

上轮对照图固定取测试集**第108—171点**，一共64点，将该64×125矩阵送进模型，得到同形状64×125重建。整个橙色虚线都来自这一个窗口的一次前向输出。

它不是对每个时刻另选一个窗口。第108点对应该窗口第1个输出，第140点对应第33个输出，第171点才对应最后一个输出。这个片段是网页已有的默认片段，本轮没有按效果好坏重新挑选。

例如要讨论第140点，有以下三种不同对象：

| 目的 | 取哪个窗口 | 读哪个输出 |
|---|---|---|
| 解释当前选择片段的重建 | 固定108—171 | 第33个输出 |
| 当第140点刚到达时作出判断 | 77—140 | 最后一个，即第64个输出 |
| 当前网站连续回放 | 所有包含140的完整窗口 | 各窗口中对应140的输出取平均 |

对于内部点140，所有覆盖窗口起点从77到140，分别为77—140、78—141、……、140—203，共64个。固定108—171是其中一个。

**具体数字也不相同。** STAM在第140点的125测点平均输入为0.660691；固定108—171窗给出的平均重建为0.685534；77—140窗的末点重建为0.709739；当前覆盖窗口合并重建为0.691598。它们是不同上下文下的真实输出，不是同一个值的不同画法。

如果想模拟逐时刻到来的输入，一个自然的候选是“最后一个点”规则：时刻140用77—140的末点，时刻141用78—141的末点，依次推进。这样不会使用140以后的观测来给140作判断，但它仍是对已经到达的140重建，不是在139预测未来140。

此规则值得单独实验，不能直接替换当前回放后保留旧阈值与成绩：

- 当前完整窗口包可支持第64—2397点的末点序列；最前63点没有完整历史窗口，需要明确等待策略或另建补齐结果。
- 每窗的掩码固定，但窗口上下文改变，会影响末点输出。
- 误差分布发生变化，必须配套重新评价。现有独立窗口阈值是对全部窗口的所有位置统一选出的，不是专门针对末点选出的。
- 本轮离线抽取显示，在第108—171点，末点序列平均重建振幅为STAM 0.065912、SMST 0.080224；当前合并序列为0.011593、0.019774。末点序列更有起伏，不自动意味着更准确或更少误报。

建议讲模型时使用“固定窗口整段重建”；讨论模拟实时判断时再增加“窗口末点序列”独立对照。当前网站继续保持已接受的覆盖窗口合并规则。

## 老师说的静态、动态，用大白话理解

**静态插入：题目出一次，保存下来，以后反复用同一套题。**

例如先把第19—42点的某些变量改掉，生成相应标签，保存为测试数据。以后两个模型都检测它，再打开网站它也不变，这样比较才稳定。

**动态插入：训练每一轮，重新出一套题。**

第一轮可能改第19—42点的电流；第二轮改另一个区间的几个电压；第三轮又换位置、变量或素材。每次重新生成这轮的数据和标签，然后训练，让模型见到更多变化。当前训练包装器从基础训练数组重新构造，再切成窗口，不是网站播放时一直往同一份数据无限叠加异常。

两者与页面“替换/混合”是不同问题：

- 静态/动态问的是：这套异常**什么时候重新生成**。
- 替换/混合问的是：异常素材**怎样放进原数据**。
- 替换：原值0.2，素材0.9，结果直接变0.9。
- 混合：素材权重0.7，结果为0.2×0.3＋0.9×0.7＝0.69。

“动画在播放”不等于动态插入；同一套预存案例播放100次，仍然是固定案例。当前八例是替换/混合×四种素材。老师原话的静态/动态×四类异常还需单独说明，不能只因都是8例就视为同一分类。

## 一次异常插入，会改全部125个变量吗

**一般不会。** 典型步骤是：选中一些窗口 → 在窗口内选一段时间 → 随机选择部分变量 → 对这片“行×列”的区域构造异常 → 生成同尺寸标签。

现有 `demoNew03.py` 给每列生成随机数，通常选中约30%的变量，并保证至少选中一列；不是每次恰好30%，更不是默认所有列都变。软替换、均匀替换、峰值噪声主要作用于选中列。

当前网页八案例为了能反复演示，固定使用清洁测试底稿第108—171点、固定32个变量；所有125列仍进入模型。大部分案例在局部第19—42点构造，峰值在局部第31点改变数值。这是受控演示的固定选择，不能说成历史训练每次都选这32列。

**历史长度调整有例外。** 它的旧实现对区间整行重复或移位，会影响全部列甚至区间外数值，却仍只给先前选中列和局部时间打标签。这是实现不一致，不是建议采用的标签规则。网页受控长度案例已经限定只修改选中区间与32列，后面的时间位置不变。

## 数值矩阵、标签矩阵和时刻标签

数值矩阵就是一张表：每行是一个时刻，每列是一个变量。标签矩阵是同样大小的另一张表，0表示这个格子正常，1表示这个格子被标记为异常。

假设有4个时刻、3个变量，只修改t2、t3的电流：

| 时刻 | 电压标签 | 电流标签 | 温度标签 | 汇总后的时刻标签 |
|---|---:|---:|---:|---:|
| t1 | 0 | 0 | 0 | 0 |
| t2 | 0 | 1 | 0 | 1 |
| t3 | 0 | 1 | 0 | 1 |
| t4 | 0 | 0 | 0 | 0 |

**汇总是横着看每一行：这一时刻有任一列为1，该时刻就为1。** t2和t3异常，不会让t1和t4跟着异常，更不会把整个64点窗口全部置1。

如果说“第19—42点整段异常”，通常因为这24行每一行都有选中变量被标了1；不是因为区间里偶然出现一个1就把其他所有行染成异常。

连续为1的时刻才组成异常区间。例如时刻标签 `0,1,1,0,1,0` 表示两段异常，分别是第2—3点与第5点，不是第2—5点一整段。

### 标签并不总由“数值变了没”反推

标签按构造规则生成，不能简单用“新值不等于旧值”逐格猜标签。

- 峰值：网页只改变第31点的选中变量，但将前后4点一起标记，所以标签覆盖第27—35点。这是明确规定的邻域标签。
- 混合：两端权重渐变为0时，端点可能保持原值，标签仍按构造的目标区间生成。
- 有原始标签时，一般按对应格子做逻辑或：原来或新增标签任一个为1，最终格子就为1。当前历史脚本有不同测试包装路径，部分固定注入入口直接保存新标签；正式清洁底稿标签原本全0，因此本批数据不据此产生额外差别。
- 已知22个整体标签正常却发生实质变化的历史时刻，说明历史数据/标签来源还需追溯；当前不会自行重标。

## 真实异常标签和模型报警是两件事

上面的0/1是我们构造出来的“答案”，用于训练或核对。模型报警来自另一条计算：

1. 对同一时刻125个变量分别计算输入与重建的平方差。
2. 对125项取平均，得到这一个时刻的异常分数；回放先对覆盖窗口平方误差平均。
3. 分数超过阈值，模型才报警。
4. 将模型报警与真实时刻标签比较，得到TP、FP、FN、TN。

所以，**有一个变量被标异常，会让这一时刻的真实标签为异常；但不保证模型一定报警。** 只有少数变量异常时，其误差可能被125维平均稀释，这正是可能漏检的原因之一。

此外，PA-F1中“异常段只要命中一点就补齐整段”是评价阶段的另一套计分规则，它不改原始标签，也不代表原始模型在该段每一点都报警。当前回放累计矩阵与逐点F1使用原始逐点报警。

训练损失也有值得进一步研究的细节：当前BND损失先把每时刻125列误差取平均，再将这一行的标签做任一列为1的汇总。于是一个变量异常时，对该时刻的整体误差应用异常目标，并非对125个格子分别应用正常/异常目标。这可能影响正常变量的细节重建，但其因果影响需新实验验证，不能仅凭读代码归因。

## 本轮新增的代码核查发现

当前两模型的 `demoNew03.py` 哈希相同。服务器内存控制探针确认：

- 训练调用传入 `length_adjust_ornot=True`，该分支将峰值的下界设为0，正的随机类型值已被软替换/均匀替换/峰值分支覆盖，长度调整没有正常可达路径。
- 在另一条 `False` 路径中，当前默认配置的长度概率虽为0，代码的剩余区间仍可落入长度调整分支。控制样本128次中观察到35次进入长度分支。
- 同一控制实验中，前三类只改随机选中的部分列；长度分支出现125列全改而标签仍只覆盖部分列。

这只证明当前代码的执行语义，不能恢复未保存的历史每轮随机样本。探针使用内存测试数组、没有修改研究数据、没有训练和保存模型。参数名字/报告描述不能替代真实分支核对。
