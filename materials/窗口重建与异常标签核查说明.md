## “单个窗口重建”到底用哪个窗口

上轮对照图固定取测试集**第108—171点**，一共64点，将该64×125矩阵送进模型，得到同形状64×125重建。整个橙色虚线都来自这一个窗口的一次前向输出。

它不是对每个时刻另选一个窗口。第108点对应该窗口第1个输出，第140点对应第33个输出，第171点才对应最后一个输出。这个片段是网页已有的默认片段，本轮没有按效果好坏重新挑选。

例如要讨论第140点，有以下三种不同对象：

| 目的 | 取哪个窗口 | 读哪个输出 |
|---|---|---|
| 解释当前选择片段的重建 | 固定108—171 | 第33个输出 |
| 当第140点刚到达时作出判断 | 77—140 | 最后一个，即第64个输出 |
| 当前网站连续回放 | 所有包含140的完整窗口 | 各窗口中对应140的输出取平均 |

对于内部点140，所有覆盖窗口起点从77到140，分别为77—140、78—141、……、140—203，共64个。固定108—171是其中一个。

**具体数字也不相同。** STAM在第140点的125测点平均输入为0.660691；固定108—171窗给出的平均重建为0.685534；77—140窗的末点重建为0.709739；当前覆盖窗口合并重建为0.691598。它们是不同上下文下的真实输出，不是同一个值的不同画法。

如果想模拟逐时刻到来的输入，一个自然的候选是“最后一个点”规则：时刻140用77—140的末点，时刻141用78—141的末点，依次推进。这样不会使用140以后的观测来给140作判断，但它仍是对已经到达的140重建，不是在139预测未来140。

此规则值得单独实验，不能直接替换当前回放后保留旧阈值与成绩：

- 当前完整窗口包可支持第64—2397点的末点序列；最前63点没有完整历史窗口，需要明确等待策略或另建补齐结果。
- 每窗的掩码固定，但窗口上下文改变，会影响末点输出。
- 误差分布发生变化，必须配套重新评价。现有独立窗口阈值是对全部窗口的所有位置统一选出的，不是专门针对末点选出的。
- 本轮离线抽取显示，在第108—171点，末点序列平均重建振幅为STAM 0.065912、SMST 0.080224；当前合并序列为0.011593、0.019774。末点序列更有起伏，不自动意味着更准确或更少误报。

口头解释当前片段时应说“固定窗口整段重建”。“窗口末点序列”只作为研究讨论，不据此新增网页对照或替换回放。

## 老师说的静态、动态，用大白话理解

**静态插入：题目出一次，保存下来，以后反复用同一套题。**

例如先把第19—42点的某些变量改掉，生成相应标签，保存为测试数据。以后两个模型都检测它，再打开网站它也不变，这样比较才稳定。

**动态插入：训练每一轮，重新出一套题。**

第一轮可能改第19—42点的电流；第二轮改另一个区间的几个电压；第三轮又换位置、变量或素材。每次重新生成这轮的数据和标签，然后训练，让模型见到更多变化。当前训练包装器从基础训练数组重新构造，再切成窗口，不是网站播放时一直往同一份数据无限叠加异常。

这里必须明确：**轮次epoch不等于批次batch。** 一轮是把这一轮训练数据完整学一遍；每轮包含许多批次，每批送入一组窗口并更新参数。

当前实现顺序是：

1. 每轮开始，从基础训练文件重新读取序列。
2. 将完整序列分成互不重叠的64点块：1—64、65—128、129—192……，最后不足64点用末值补齐。
3. 在这些块中抽取一部分，随机选构造类型、时间位置和变量，生成数值及标签。
4. 按原顺序拼回整段序列，去掉尾部填充。
5. 将改好的序列与标签同步切成重叠64点训练窗口，生成Global分支掩码，再按批次训练。
6. 下一轮重新生成异常，再重复以上过程。

所以，同一轮中，某个源时刻出现在两个重叠窗口、甚至分属两个训练批次时，异常数值及异常标签保持一致；不会因为再次输入就重新构造一遍。下一轮同一源窗口可能变成另一种异常，也可能不被抽中。窗口掩码是另外的处理，不能把遮蔽成0误认为又插入了一次异常。

报告3.3明确写每个epoch开始重新生成，报告2.3及3.3描述了非重叠插入→拼接→重叠训练；这两点与服务器一致。

## 插入比例、异常长度和变量选择是三个独立问题

**25%插入比例不等于将一个64点窗口分成四份、随机改其中16点。** 64点本身是当前非重叠插入块的长度，比例控制抽取多少块，区间长度由另一个参数控制。

例如有100个64点块，比例25%时，当前程序抽25次块编号。它使用`np.random.choice(..., size=25)`，未关闭重复抽取，因此可能多次抽到同一个块；并非对每个块独立抛一次25%概率的硬币，也不保证25个不同块。每次构造基于抽取前的原块副本，最后写回时同块的后一次覆盖前一次，标签也一并覆盖。

当前converter配置`a_rate=0.7`。5593个训练时刻分成88个非重叠块，默认一次生成组最多128块，因此这组会抽`int(88×0.7)=61`次。受控探针固定种子901抽到39个不同块，种子903抽到43个；这只是重现抽样语义的人工控制实验，不是历史训练覆盖率。

异常区间长度单独使用`replacing_rate=(0.4,0.6)`：`randint(int(64×0.4), int(64×0.6))`即`randint(25,38)`，结果为**25—37点**。随机起点须能让区间完整落在64点块中，不要求与16点分段对齐。参数文件中的`--replacing_rate_max`并未被此处采用，当前实际使用的是`src/constants.py`中的数据集配置。

前三类构造再随机选择部分变量，通常约30%，保证至少选一列；125列时常见约38列，但不是固定38列。一次构造中的选中变量使用同一目标时间区间；软替换取来的参考列和参考起点还可以各不相同。

| 构造方法 | 当前随机实现的数值影响 | 标签覆盖 |
|---|---|---|
| 软替换 | 在选中变量的25—37点区间与参考素材混合；两端权重为0，通常实际改变中间23—35点 | 选中变量的完整25—37点区间 |
| 均匀替换 | 选中变量各取一个随机常数，连续替换25—37点 | 同一25—37点区间 |
| 峰值噪声 | 在采样区间中再选一个时刻，仅改变选中变量在这一时刻的值 | 峰值前后各4点；在64点边界截断后，共5—9点 |
| 旧长度调整 | 若进入该分支，当前配置只走拉长：取6—18个源点，重复2/3/4倍形成24—36个目标点，并移动后续行以保持窗口64点；会影响全部125列 | 只给选中变量的24—36点目标区间打标，与实际修改范围不一致 |

长度分支还有缩短代码，但判定界限为19，而当前采样长度为25—37，因此该配置下不会走缩短。上表描述随机研究函数；网页已有受控案例固定目标24点、32列，峰值只改1点并标9点，两者不是同一组样本或同一时长设置。

两者与页面“替换/混合”是不同问题：

- 静态/动态问的是：这套异常**什么时候重新生成**。
- 替换/混合问的是：异常素材**怎样放进原数据**。
- 替换：原值0.2，素材0.9，结果直接变0.9。
- 混合：素材权重0.7，结果为0.2×0.3＋0.9×0.7＝0.69。

“动画在播放”不等于动态插入；同一套预存案例播放100次，仍然是固定案例。当前八例是替换/混合×四种素材。老师原话的静态/动态×四类异常还需单独说明，不能只因都是8例就视为同一分类。

## 一次异常插入，会改全部125个变量吗

**一般不会。** 典型步骤是：选中一些窗口 → 在窗口内选一段时间 → 随机选择部分变量 → 对这片“行×列”的区域构造异常 → 生成同尺寸标签。

现有 `demoNew03.py` 给每列生成随机数，通常选中约30%的变量，并保证至少选中一列；不是每次恰好30%，更不是默认所有列都变。软替换、均匀替换、峰值噪声主要作用于选中列。

当前网页八案例为了能反复演示，固定使用清洁测试底稿第108—171点、固定32个变量；所有125列仍进入模型。大部分案例在局部第19—42点构造，峰值在局部第31点改变数值。这是受控演示的固定选择，不能说成历史训练每次都选这32列。

**历史长度调整有例外。** 它的旧实现对区间整行重复或移位，会影响全部列甚至区间外数值，却仍只给先前选中列和局部时间打标签。这是实现不一致，不是建议采用的标签规则。网页受控长度案例已经限定只修改选中区间与32列，后面的时间位置不变。

## 数值矩阵、标签矩阵和时刻标签

数值矩阵就是一张表：每行是一个时刻，每列是一个变量。标签矩阵是同样大小的另一张表，0表示这个格子正常，1表示这个格子被标记为异常。

假设有4个时刻、3个变量，只修改t2、t3的电流：

| 时刻 | 电压标签 | 电流标签 | 温度标签 | 汇总后的时刻标签 |
|---|---:|---:|---:|---:|
| t1 | 0 | 0 | 0 | 0 |
| t2 | 0 | 1 | 0 | 1 |
| t3 | 0 | 1 | 0 | 1 |
| t4 | 0 | 0 | 0 | 0 |

**汇总是横着看每一行：这一时刻有任一列为1，该时刻就为1。** t2和t3异常，不会让t1和t4跟着异常，更不会把整个64点窗口全部置1。

如果说“第19—42点整段异常”，通常因为这24行每一行都有选中变量被标了1；不是因为区间里偶然出现一个1就把其他所有行染成异常。

连续为1的时刻才组成异常区间。例如时刻标签 `0,1,1,0,1,0` 表示两段异常，分别是第2—3点与第5点，不是第2—5点一整段。

### 标签并不总由“数值变了没”反推

标签按构造规则生成，不能简单用“新值不等于旧值”逐格猜标签。

- 峰值：网页只改变第31点的选中变量，但将前后4点一起标记，所以标签覆盖第27—35点。这是明确规定的邻域标签。
- 混合：两端权重渐变为0时，端点可能保持原值，标签仍按构造的目标区间生成。
- 有原始标签时，一般按对应格子做逻辑或：原来或新增标签任一个为1，最终格子就为1。当前历史脚本有不同测试包装路径，部分固定注入入口直接保存新标签；正式清洁底稿标签原本全0，因此本批数据不据此产生额外差别。
- 已知22个整体标签正常却发生实质变化的历史时刻，说明历史数据/标签来源还需追溯；当前不会自行重标。

## 真实异常标签和模型报警是两件事

上面的0/1是我们构造出来的“答案”，用于训练或核对。模型报警来自另一条计算：

1. 对同一时刻125个变量分别计算输入与重建的平方差。
2. 对125项取平均，得到这一个时刻的异常分数；回放先对覆盖窗口平方误差平均。
3. 分数超过阈值，模型才报警。
4. 将模型报警与真实时刻标签比较，得到TP、FP、FN、TN。

所以，**有一个变量被标异常，会让这一时刻的真实标签为异常；但不保证模型一定报警。** 只有少数变量异常时，其误差可能被125维平均稀释，这正是可能漏检的原因之一。

此外，PA-F1中“异常段只要命中一点就补齐整段”是评价阶段的另一套计分规则，它不改原始标签，也不代表原始模型在该段每一点都报警。当前回放累计矩阵与逐点F1使用原始逐点报警。

## “先平均误差，再按整行标签处理”意味着什么

以某一时刻为例：先对125个变量分别计算输入与重建的平方差，再平均成一个分数e。标签也汇总成一个答案：125格全为0，这行正常；只要一格为1，这行异常。

接下来并非所有行都追求e越小越好：

- 正常行：e越小，训练损失越小，模型被推动着重建准确。
- 人工异常行：e还不够大时，e增大反而使训练损失减小；达到边界后，该项不再推动误差增大。

可以理解为“正常题学会，人工异常保留明显差异”，这样最后才可能靠误差大小区分正常与异常。报告4.1也是这个目标。它并不是把所有正常、异常输入都重建得越像越好。

代码具体为`L=mean(ReLU(2×BNS−y×e))`，正常y=-1、异常y=+1。当前converter的BNS=0.2086，边界C=0.4172：正常项为C+e，异常项为max(0,C−e)。边界是训练中的停止推动条件，不是最终报警阈值，也不是强制误差不能超过它。

受控例子：125项平方误差均为0.01时，全部正常的行损失为0.4272；只将第一个变量标签改成异常，该行损失变为0.4072。若异常行平均误差增到0.10，损失下降为0.3172，因此优化器会偏好后一种情况。此例只说明重建损失项，模型二还加空间正则项。

**逐行处理会丢失“哪几列异常”的细分。** 若只有电流被标1，当前损失给这一整行的平均误差施加异常目标。其他124列即使未插入异常，也没有在该项中单独保留“误差应降低”的目标。内存梯度探针确认：在各列有相同非零残差的例子中，改一列标签便使未标异常列的梯度方向一起反转。不能因此保证真实训练每列误差一定上涨，但它确实没有将推动误差增大的作用限定在异常格子。

算重建误差时的参照`elem=d`是插入后的数据，不是插入前的干净真值。不能把该目标直接解释成“有干净真值监督的去噪还原”。

报警阶段仍是平均平方误差超过检测阈值才报警；真实标签用于核对答案。只有一个变量标签异常，并不保证平均分超过阈值。当前阈值是既有的事后回看评价口径，不能视为已经验证过的在线报警阈值。

另一个应记录的差异：当前训练入口实际反向传播使用BND损失，模型二还有空间正则；但返回到`accuracy_list`并由网页读取的历史`loss`字段是普通MSE的批次均值平均，并非完整优化目标。现有“训练损失”图标题容易被理解为BND总损失；本轮只报告该口径，没有擅自修改页面。

## 本轮新增的代码核查发现

当前两模型的 `demoNew03.py` 哈希相同。服务器内存控制探针确认：

- 训练调用传入 `length_adjust_ornot=True`，该分支将峰值的下界设为0，正的随机类型值已被软替换/均匀替换/峰值分支覆盖，长度调整没有正常可达路径。
- 在另一条 `False` 路径中，当前默认配置的长度概率虽为0，代码的剩余区间仍可落入长度调整分支。控制样本128次中观察到35次进入长度分支。
- 同一控制实验中，前三类只改随机选中的部分列；长度分支出现125列全改而标签仍只覆盖部分列。

用大白话说，类型选择像把0—1的一段数轴划给四种方法。当前默认参数下，训练这条True路径把它分成约50%软替换、15%均匀替换、35%峰值、0%长度调整：峰值分支提前接走了所有剩余的正随机数。另一False路径则约为50%/15%/15%/20%，即使长度配置写0也仍有20%的数轴进长度分支。比例指构造尝试的理论分配，不能当成最终不同窗口的实测比例。

问题发生在模型收到数据以前的异常生成程序，和无卡运行、网页加载或图表渲染无关。当前代码不能支持“每轮都按配置正常覆盖四类构造”的结论。修复后需要另做实验验证，不能只修改页面文字就视为解决。

报告还将异常项对误差的梯度写为+1；按此处公式，在低于边界时应为-1，梯度下降才会推大误差。报告说各窗口损失相加，代码则取平均；二者缩放不同，需在复现实验时写清。

这只证明当前代码的执行语义，不能恢复未保存的历史每轮随机样本。探针使用内存测试数组、没有修改研究数据、没有训练和保存模型。参数名字/报告描述不能替代真实分支核对。
